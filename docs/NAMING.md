# Names, old and new

What the product is called, what kept an older name on purpose, and how
renamed things upgrade. Never rename a kept name without a migration.

## Spriessen, Spreissen and ultiv

The product is Spriessen ("to sprout"; `@spriessen/*` packages, `SPRIESSEN_*` env keys, the `x-spriessen-token` webhook header; the old `x-spriessen-user` identity header is no longer read, identity is the sign-in session). The short-lived misspelling Spreissen was a clean cut: `SPREISSEN_*` keys and `x-spreissen-*` headers are NOT read any more, so anyone who set them must switch to the `SPRIESSEN_*` / `x-spriessen-*` names. Only what a device or bot had already saved under it carries over: the `spreissen.*` browser keys (adopted into `spriessen.*`, see `apps/web/src/lib/stored-key.ts`) and a bot's on/off switch for the built-in `spreissen` skill (`RENAMED_BUILTINS` in `packages/mind/src/skills/store.ts`). Kept on purpose with the old `ultiv` spelling: the stored record names (`ultiv.sessions`, `ultiv.mem.*`, `ultiv.kv.<profile>`, …), chord remote and tool/plugin ids (`ultiv.session`, `ultiv.bash`, …), the vault key salt, the sandbox image tag and VM names (`ultiv-sandbox:latest`, `ultiv-<hash>`), the deprecated `ULTIV_*` env fallback (`readEnv` in `@spriessen/core`, one warning per key) and the legacy `x-ultiv-token` webhook header, the GitHub repository (`orgrigami/ultiv`), the local folder and the tmux session. Never rename those without a migration.

## Teams were called departments

Renamed 2026-11-07 in code, contracts, tools, REST, routes and prose. Stored rows upgrade on read through `packages/mind/src/migrate/teams.ts` (`renameLegacyTeams`, wired as the `migrate` of `ultiv.org` v2, `ultiv.profiles` v3 — its v1 `canInitiate` fix now runs only from v1 — and `ultiv.mem.facts`/`ultiv.mem.proposals` v2: `departmentId`/`departments` keys, `kind`/`scope` `"department"`, the old `department_*`/`departments_list` names in tool lists and approval rules); vault sidecars read their old home through `legacyHomeOf` (`packages/ext/src/vault.ts`); old audit lines read renamed (`parseLines` in `audit/tail.ts`); MCP team folders move from `dept-<id>` to `team-<id>` before the mind opens (`upgradeMcpTeamHomes`), and both segment prefixes still parse; `/api/org/departments…` and `?department=` still reach the team routes; `/crew/dept/$departmentId` redirects. Kept on purpose: existing team IDS (`dept-<slug>`; new teams get `team-<slug>`) — they name each team's VM folder, shared store and gid — the shared-memory doc address `dept:<owner>:<teamId>` (`teamKey`) and the org VM's Linux groups `ultiv-d<gid>`. The org VM's mount moved to `/home/team-shared` (the mount is in the VM's fingerprint, so the org VM is recreated at its next use; the host store is the source of truth).
