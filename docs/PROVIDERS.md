# Models, providers and Jev

How the mind reaches language models and the Jev decision model. The
owner-facing version (which keys to set, the overlay file) is in the
README's Models section.

- **Owner rule: the mind is the only provider consumer.** Every LLM chat/generation goes through pi-durable conversations inside `@spriessen/mind` (`converse.turn` = `submit` → `wait` → `commit`), never raw `models.complete()` in app code. Models are addressed as `provider/model` (split at the FIRST slash: `openrouter/anthropic/claude-x`); bare ids stored before 2026-10-29 were kenari ids and normalize to `kenari/<id>` (`providers/refs.ts`, `readProfiles`). Conversations start on `SPRIESSEN_MODEL` (fallback `DEFAULT_MODEL_FALLBACK` in `packages/mind/src/config.ts`, used when that provider is configured, else the first listed model — `catalog.defaultRef()`); sessions override via `converse.configure(conversation, { model, effort })` (durable `conversation.configure`; read back with `agentOf`, which snaps out-of-list efforts to the model's default). Usage surfaced to contracts/UI is TOKENS only — cost stays internal to pi-ai (rates come from models.dev). Compaction compacts at **75%** of each model's context window (`compactionFor` in `providers/refs.ts`, served as a GETTER on Harness `settings.compaction` so thresholds follow catalog refreshes). Jev decisions have an independent entry: `mind.decide.*` — the same faculty also appears as `jev`/`jev_score`/`jev_pick`/`jev_rate` agent tools via the decision plugin (descriptions are first-person faculty: "your own decision faculty, Jev" — Jev is part of each bot's own mind, never narrated as an external helper).
- **The model catalog is models.dev, per configured provider** (`packages/mind/src/providers/`): `catalog.ts` parses `https://models.dev/api.json` tolerantly and merges the owner's overlay (`MODELS_OVERLAY`, default `<data>/models.local.json`, same format — extra models, extra/local providers, endpoint overrides); `catalog-cache.ts` keeps the raw body in `MODELS_DEV_CACHE` (default `<data>/models-dev.json`) with its ETag; `kenari.ts` revalidates the kenari provider against the gateway's own `/v1/models` listing (`KENARI_MODELS_URL`, default `https://kenari.id/v1/models`, cache `KENARI_MODELS_CACHE`, TTL `KENARI_MODELS_TTL_HOURS` 6) — the live listing REPLACES kenari's model set (the gateway runs ahead of models.dev; IDR pricing is ignored, models.dev USD costs survive for shared ids); `models.ts` (`ModelCatalog` service, `mind.models`) boots from the caches, only waits on the network when there is no cache, revalidates in the background past the TTLs and re-registers providers live; `MODELS_DEV_URL=off` never fetches anything (smoke, offline — it disables the kenari fetch too). `wire.ts` turns each provider into a pi-ai `createProvider`: enabled when one of its key-shaped models.dev `env` vars is set (`SPRIESSEN_PROVIDERS` narrows; a keyless local server needs to be listed there); the models.dev `npm` package picks the pi-ai API (`@ai-sdk/openai-compatible`/groq/cerebras/together/deepinfra/perplexity/openrouter → openai-completions, `@ai-sdk/openai`/xai → openai-responses, anthropic, google, mistral; Bedrock/Vertex/Azure/Cohere/… are skipped); `${VAR}` endpoint parts expand from env; only chat, tool-calling, text-in/out, non-deprecated models are listed. Efforts are PER MODEL from models.dev `reasoning_options` → `thinkingLevelMap` (effort `none` = off; a bare toggle = off/high; a reasoning model with no listed control offers none); the default effort is the lowest offered. Provider ids stay models.dev's on purpose: pi-ai detects wire quirks (thinking format, max_tokens naming) from id and base URL. REST: `GET /api/models` (`id` = `provider/model`, grouped by `providerName` in the pickers), `GET /api/models/catalog`, `POST /api/models/refresh`. Never use `response_format: json_object` — it hangs some gateways (kenari); ask for strict JSON in the prompt. Kenari models misreport their own id (`model_used` says gpt-4o/gpt-4.1) — ignore it; routing follows the requested id.
- **Typesafe.AI (Jev)** — `@typesafe-ai/sdk`, `client.systemOne({ state, questions })` with `noul`/`choice`/`score`/`box` builders; key `TYPESAFE_API_KEY`, model `jev-latest` (`TYPESAFE_MODEL` overrides), endpoint `TYPESAFE_BASE_URL` (default `TYPESAFE_DEFAULT_BASE_URL` in config.ts, passed explicitly so a blank line never reaches the SDK as an empty URL). Blank env values mean unset for keys, `SPRIESSEN_MODEL`, `SPRIESSEN_PROVIDERS` and `MODELS_DEV_URL` (only `off` disables the fetch). Jev is a typed decision model, not a chat provider: `decide/decide.ts` wraps it behind the narrow `JevGateway` seam (`decide/gateway.ts`) so tests substitute fakes. Unconfigured keys fail LOUDLY but lazily: `decideService(undefined)` fails every call with `Unavailable`; the decision plugin simply isn't installed.
- `.env` holds provider keys — server-side only; never commit, print, or ship to the client. Load it with `vp node --env-file=…` (or the `dev`/`start` scripts), never by echoing it.
- **The fallback model** (Settings › Fallback model, `ultiv.settings` `fallbackModel`): a FAILED background task run retries ONCE on it (`tasks/run.ts` `rescueOnFallback`, a `[fallback]` note in the task's transcript, the conversation's own model restored after; a rescue that fails again stands). Catalog-validated on save (`PUT /api/settings/fallback-model`); chats with the owner never fall over silently.
