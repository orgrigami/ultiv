# The web client

`apps/web`: React 19 + TanStack Router + shadcn on Base UI + Tailwind 4, no
Effect in the client. `apps/web/DESIGN.md` is the visual authority and
`apps/web/PRODUCT.md` the product truth; this file is the engineering map.
The short rules every change must follow are in AGENTS.md.

- **Routing: TanStack Router, file-based.** Routes live in `apps/web/src/routes/`; `__root.tsx` is the one layout (desktop rail + phone tab bar from `components/app-nav.tsx`, `main` sets `--chat-bottom` for the floating composer) and carries the root `errorComponent`/`notFoundComponent` (`components/route-error.tsx`). ONE nav on every width: Now (Needs you count badge) · Chats · Crew · Settings; `lib/nav.ts` `sectionOf(path)` maps every route to one of the four on whole path segments so both bars mark the same place (`aria-current`); `/` , `/c/…` and `/history` are Chats, `/now` and the old `/needs` are Now. The sidebar adds New chat (N), Find (Cmd/Ctrl-K), the crew roster and a Recents list (`lib/chats.ts` `pastChats`, shared with Past chats and the switcher); the phone tab bar adds a Find tab, and Past chats opens from the chat header's "…" popover. On `lg+` the work dock (`components/work-pane.tsx`, state in `lib/work-pane.tsx` + `lib/work-stack.ts`) floats beside the chat and holds several tabs at once (a task, a file, memory, Needs you, a room); the strip at its top switches them, opening from the chat focuses a matching tab or adds one, opening from inside the dock joins the active tab's trail (its root never falls off), and the dock keeps at most five tabs (the oldest not being looked at gives way); below `lg` the active tab is a sheet. Every non-chat screen renders through `Page` (`components/page.tsx`): title row with the screen's actions beside it (they wrap under the title on phones), optional lead, hairline only when there is a lead; nested screens go back through the one `BackLink` idiom; Now renders `wide` with a two-column grid at `lg`. `components/quick-switcher.tsx` owns Cmd/Ctrl-K, N and ? (rules and ranking in `lib/quick-switch.ts`; bare keys never fire while typing). Routes: `/` (chat with the current bot, `?bot=<id>`; onboarding when there are no bots), `/c/$sessionId` (one chat), `/now` (the check-in, `routes/now.tsx` + `components/now/`: Needs you first (`NeedsList compact`), then running tasks across bots and clean finishes from the last day (`lib/now.ts`, the app's task list), goals in motion (`GET /api/projects`) and the newest files (`GET /api/artifacts?limit=8&sources=1`, each with the chat it came from: `rest/artifact-source.ts` resolves a file's conversation to its chat, or a task's file to the chat that spawned the task; `/meta` always carries `source`; `components/file-source.tsx` draws the link in the Files tab and the file pane too). Needs you: `lib/needs-you.ts` `needsYouItems` folds the approvals and tasks the app already holds with `GET /api/needs-you`, which loads on mount, window focus, visits and the `needs-you` live signal — NO polling; failed tasks and escalations are dismissable per device in localStorage; PARKED engine tasks — pi-durable tasks cut off by restarts `settings.restartLimit` (5) times in a row, which never run again by themselves — come from `converse.parked()` (`harness.inspect`, `blocked`/`restart_limit`), filtered to the caller's bots by `profiles.scopeOf`, and the row's Retry calls `POST /api/needs-you/parked/:taskId/retry` → `converse.retryParked` (`harness.retryTask`); another owner's or an unmapped task gets the unknown-task 404), `/crew` (the bot list + links to all routines, bot talks, past chats), `/crew/$botId` (the bot's character centered, pill tabs with live counts from `lib/profile-summary.ts`, file-style `NavCard`s on Overview; `?tab=instructions|memory|projects|routines|access|files|activity|tests` (`components/profile-tabs.tsx`; the Work tab's id stays `projects`); the profile reuses `MemoryContent`, `RoutinesContent` with `botId`, `ApprovalModeChoice`/`AutoApproveField`; Activity is a read-only `/api/audit?profile=` view), `/settings` (server check, push, approval-mode explainer, links to connectors/skills/vault, theme), `/routines`, `/history` (Past chats; its filter also searches the words said in the bots' chats — a Messages section, `components/message-search.tsx`), `/rooms` ("Bot talks", `?bot=` + `?room=`), `/tools?tab=connectors|skills|vault` (one page; `/connectors`, `/skills`, `/vault` redirect into it), and redirect-only `/bots` → `/crew` and `/needs` → `/now` (`MOVED` in `lib/nav.ts`; old bookmarks and pushes; the memory-tidy push opens `/now`) and `/sessions/$sessionId` → `/c/$sessionId`. The rail (sm+, `w-64`) is the wordmark, New chat, Find, the four sections with the shared `components/crew-list.tsx` roster under Crew (picking a bot opens its chat). The chat-header pill (`bot-switcher.tsx` → `bot-panel.tsx`, same `CrewList`) is the switcher at every width; the approval-mode chip (`components/approval-mode-control.tsx`) sits next to it; New chat is the header's left button on a main chat; Past chats sits at the top of the header's "…" popover. The Chats tab returns to the last bot (`lastBot` in `lib/app-state.tsx`). `busy`/`attention` derive from the tasks/approvals the app holds, refreshed by live signals over `/push` (`docs/LIVE.md`). The router plugin regenerates `src/routeTree.gen.ts` on `vp dev` / `vp build`. It is committed, never hand-edited, and excluded from oxfmt. `src/router.ts` creates the router and registers its type.
- **Components: shadcn, style `base-nova`, on Base UI (`@base-ui/react`), not Radix.** Config is `apps/web/components.json`; add components with `vp -C apps/web exec shadcn add <name>`. Primitives live in `src/components/ui/` (badge, button, card, code-block, collapsible, dev-details, dialog, empty-state, input, input-group, list-row, scroll-area, section-header, select, separator, skeleton, spinner, textarea, trace) — reuse them (Select, SectionHeader, EmptyState/ErrorState, ListRow, DevDetails) instead of one-off markup. Dialogs are bottom sheets on phones and centred on `sm+`; menus and small popovers too: anchored on `sm+`, a bottom sheet on phones through `components/ui/menu-sheet.tsx` (`sheetPositioner` + the `.menu-sheet` CSS, `sheetRow`/`sheetRowStacked` rows, `SheetHeading`, a backdrop, popovers `modal` on phones) — a new menu uses those pieces. Markdown goes through `LazyMarkdown` (react-markdown + shiki in a lazy chunk). Icons: `lucide-react`.
- Base UI composes with the **`render` prop, not `asChild`**. When a `Button` renders a non-button element (e.g. a router `Link`), also pass `nativeButton={false}` — see `routes/index.tsx`.
- **Styling: Tailwind 4, CSS-first** — no `tailwind.config`; theme tokens and the `dark` variant live in `src/index.css` (imports `tailwindcss`, `tw-animate-css`, `shadcn/tailwind.css`, Geist Sans + Geist Mono variable fonts). Use the semantic tokens (`bg-background`, `text-muted-foreground`, …), not raw colors. ALL tokens live in `index.css`: a `--gray-1…12` neutral ramp per theme that the shadcn names map onto, one accent (`--accent-tone`, amber; `--live` aliases it), semantic `--success` (= `approve`, `ok`), `--deny` (= `destructive`), `--warning` (YOLO, care) and `--signal` (needs you), all AA on background/card/popover in both themes; the type scale `text-meta` 12/16, `text-ui` 14/20 (body default), `text-chat` 16/24 (messages via `.chat-prose`, the composer), `text-title` 20/28; icons are lucide only at one 1.75 stroke (`svg.lucide`), 16 px inline, 20 px rail, 24 px tab bar; spacing is a 4 px grid with 12/24 px gutters and 44 px touch targets. The world (DESIGN.md is authority; `apps/web/PRODUCT.md` the product truth): a quiet dark theme, deep blue-black ground, warm ivory ink, four lightness elevation tiers, hairline rules; Geist Mono is the data voice (`.readout`, `.tnum`); one reserved red light (`--signal`) for what demands the owner, `--live` amber for working, `--ok` for settled; each bot gets a deterministic character from its id (`lib/avatar.ts` `characterOf`, drawn by `components/bot-avatar.tsx`; idle is still, `mood` thinking/alert animate and stop under reduced motion); the brand lives in ONE module, `lib/brand.ts` (name, tagline, colors, mark geometry; `docs/design/brand.md` has the voice guide), and loading states are skeletons (`components/ui/skeleton.tsx`), not spinners. UI copy stays plain and standard: product vocabulary only (Crew, Bot talks, Routines, Tools, Vault), no themed roleplay labels, standard status words (connected/connecting/disconnected). Floating chrome uses `.chrome-float` (translucent + offset shadow). State renders through `components/state-mark.tsx` (`Mark`), never raw colored dots. Radii: base `--radius: 0.625rem` (lg 10 for fields and buttons, xl 15 for cards and lists, 2xl 20 for tiles and the owner's message card, 3xl 25 for sheets, the work dock and empty states), pills stay `rounded-full`; the phone tab bar's height lives in one `--tabbar-h` that the bar, the chat's `--chat-bottom` and every page's bottom reserve read. Named-thing lists (Needs you, Past chats, Bot talks) are one card-of-rows: `rounded-xl` container with `p-1`, `rounded-lg` rows, 56px two-line rows inside a 44px world. Tabs are one idiom everywhere: the pill strip (`variant="filter"`). Motion stays at 200 ms or less, presses scale to .98 (`.press`, and in `Button`), and every animation stops under `prefers-reduced-motion`.
- `cn()` comes from the `cn` package (`src/lib/utils.ts` re-exports it), not clsx + tailwind-merge.
- Alias `@/*` → `apps/web/src/*`, declared in `apps/web/vite.config.ts` (`resolve.alias`), `apps/web/tsconfig.json` (`paths`) and the root `vite.config.ts` (so root `vp test` resolves web component tests) — keep the three in sync.
- Chat chrome (header pill = bot switcher, composer, tab bar) floats translucent over the transcript; keep text sizes ≥ `text-xs`, border-only cards. Bot prose is the terrain (no bubble); the owner writes on a quiet raised card; long replies fold with a mask + Show more (`transcript-items.tsx`).
- Tool calls render through the presentation lens (`@spriessen/present/tool-text` `presentationOf`, re-exported at `src/lib/tool-text.ts`: human / hidden, with structured `ToolBodyData` and `humanizeToolName` for anything unlisted; `src/components/tool-trace.tsx` draws numbered rows, `src/components/tool-bodies.tsx` the shaped bodies): owner-worded titles, present tense while running, an index per call in its run, per-kind expanded views (search hits, HTTP request/response, terminal, file preview, definition-list records), EVERY tool renders in owner words (unknown/MCP tools get a humanized title with "Sent"/"Got back" receipts as their body, `tool-receipts.tsx`; everything attached to a row lines up in one `ATTACH` column, a row with nothing more to show has no chevron, and Jev's verdict shows under the call it judged), errors extracted from the payload (`errorTextOf`) into an `ErrorNote`, `jev_*` and `now` hidden as inner monologue. The task sheet's timeline renders through the SAME lens (`task-steps.ts` `toolStepOf`; it keeps no tool vocabulary of its own) and the same rows (`task-sheet/timeline.tsx` `rowsOf`: consecutive calls form one run, numbered by call; thinking is the shared `thinking-trace.tsx`); its header shows the call count and, while running, what it is doing now (`doingOf`). Per-area views live beside the lens (`admin-tool-views.ts`, `code-tool-views.ts` for `code_outline`/`code_nav`/`file_find`). `lib/tool-coverage.test.ts` reads every `defineTool` in the packages and fails when a tool falls back to its humanized name or a gated tool has no approval-card words (`approval-text.ts` `KNOWN`) — a new tool lands with both. File previews format by kind (`file-preview.tsx` frame + toolbar, `file-views.tsx` one body per kind, `lib/file-meta.ts`, `lib/delimited.ts`): one toolbar row (Preview|Table / Source, wrap — remembered per device —, copy, download, fullscreen), a body that fills the pane and owns its one scroll area; markdown renders at a 72ch measure, CSV/TSV as a table (sticky header, row numbers, numbers right-aligned), text/code shiki-highlighted with line numbers, media fitted. Fullscreen is its own dialog over the whole viewport, so it works from the phone sheet; tapping a file card's name opens the preview. Skill rows carry their enabled/disabled state; the skill sheet opens each reference file inline (REST `GET /api/skills/:profile/:name/files/:path` over `mind.skills.readFile`). Every chat owns its bot's Memory panel in place (the panel's "What X remembers" or a memory chip's "Open in Memory" with the search pre-filled); never redirect to /crew for it (the Crew profile's Memory tab is the other home of the same panel).
