# AGENTS.md — ultiv

Effect-first, AI-native web app as a pnpm-workspace monorepo. The **core is three packages**: `@ultiv/core` (kernel: shared tagged errors + the `openRuntime` promise↔Effect door), `@ultiv/ext` (the extension platform: tools, connectors, plugins, registry, vault), and `@ultiv/mind` (the entity substrate — **one runtime, one entity per profile**; user-defined profiles are the entities, the default profile is Ultius; the package keeps its working name `mind`). `apps/server` (Node 24) is a thin chord host over the mind; `apps/web` (React 19 + TanStack Router + shadcn on Base UI + Tailwind 4) is the thin client over replicated chord state; `packages/contracts` holds the TypeBox chord contracts shared by both.

## Toolkit: Vite+ (`vp`) only

**Every command goes through `vp`. Never run `npm`, `npx`, `pnpm`, `yarn`, bare `node`, `tsc`, `vite`, `vitest`, `oxlint`, or `oxfmt` directly.** vp owns the whole chain:

| Need                        | Use                                                                            | Never                                   |
| --------------------------- | ------------------------------------------------------------------------------ | --------------------------------------- |
| Install / sync deps         | `vp install` (`--frozen-lockfile` in CI)                                       | `npm i`, `pnpm i`                       |
| Add / remove a dep          | `vp add <pkg> --filter <workspace>` (`-D` dev, `-E` exact), `vp remove`        | `npm install`, `pnpm add`               |
| Inspect deps                | `vp outdated`, `vp why`, `vp list`, `vp info`                                  | `npm ls`, `pnpm why`                    |
| Run a package script        | `vp run <task>` / `vpr <task>`; one workspace: `vp run --filter <name> <task>` | `npm run`, `pnpm --filter`              |
| Local binary                | `vp exec <bin>` (in a workspace: `vp -C <dir> exec <bin>`)                     | `npx`, `pnpm exec`                      |
| One-off package binary      | `vp dlx <pkg>`                                                                 | `npx <pkg>`                             |
| Node / a TS file            | `vp node <args>`; `vpx <file.ts>`                                              | `node`                                  |
| Format + lint               | `vp check` (`--fix`), `vp fmt`, `vp lint`                                      | `oxfmt`, `oxlint`, `eslint`, `prettier` |
| Tests                       | `vp test`                                                                      | `vitest`                                |
| Dev / build / preview       | `vp -C apps/web dev` / `build` / `preview`                                     | `vite`                                  |
| Anything else pnpm-specific | `vp pm <command>` (forwards to pnpm)                                           | bare `pnpm`                             |

- Vite+ 1.4.0 (global install + `vite-plus` devDep via the pnpm catalog). Must stay ≥ 1.1.0: 1.0.0 has known advisories (fixed 1.1.0/1.3.0); 1.4.0 is OSV-clean. Upgrade with `vp upgrade`; inspect with `vp toolchain`.
- Node 24 LTS, pinned in `mise.toml` (`node = "24"`); `vp node --version` resolves the same 24.x. A bare `node`/`npm` on PATH may come from homebrew — never trust it. If `vp` itself isn't on PATH, prepend `~/.vite-plus/bin`.
- pnpm 12 is the package manager underneath (`packageManager` field), but you only ever reach it through `vp`.
- Root `package.json` scripts (`check`, `build`, `test`, `smoke`) run with `vpr <name>`. `vp check` (built-in) and `vpr check` (script) do the same thing here.

## Commands (verified)

- `vp check` — format + lint gate (`--fix` to apply). It does NOT run our project typechecks.
- `vp exec tsc -p <pkg>/tsconfig.json` — the type gate, for each of `packages/contracts`, `packages/core`, `packages/ext`, `packages/mind`, `apps/server`, `apps/web`. All six must pass.
- `vp test` — Vitest across workspaces (`packages/contracts`, `packages/core`, `packages/ext`, `packages/mind`; one package: `vp run --filter @ultiv/core test`).
- `vp -C apps/web build` — production build of `apps/web` (root `vp build` needs the `-C` target; `vpr build` wraps this).
- `vp run smoke` — boots the whole server stack on an ephemeral port, offline (`apps/server/src/smoke.ts`; delegates to the server workspace script because `vp node` cannot resolve node inside a nested `vp run`), and exercises the REST surface: owner-scoped sessions, artifact upload/download, webhook auth, cron validation, task spawn.
- `vp install --frozen-lockfile` — verifies the lockfile is in sync and passes supply-chain policy.
- `vp -C apps/web exec shadcn <cmd>` — shadcn CLI (e.g. `add <component>`), run where `components.json` lives.

Not run automatically (long-running or live):

- `vp node --env-file=.env packages/mind/src/probe.ts` — LIVE provider check (network + keys): kenari converse through the harness, Jev via the `jev_score` tool, Jev `decide` direct, plus `now` and `web_search` through the act.
- `vp run --filter @ultiv/server dev` — server with watch + `--env-file`; listens on `PORT` (default 8787).
- `vp -C apps/web dev` — web dev server.
- `vpr @ultiv/server#push:keys` — one-time VAPID key generation: appends `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` to `.env` only when absent, prints no value. Never rotate casually (every device must re-subscribe).

**Every facet reaches the app:** the server binds all interfaces IPv4+IPv6 when `HOST` is unset (`apps/server/src/listen.ts` logs one URL per facet on boot); `vp dev` and `vp preview` accept any Host name (`ALLOWED_HOSTS` narrows) and proxy `/api`, `/hooks` and `/chord` to `API_URL` (default `http://127.0.0.1:$PORT`), and the client always talks same-origin (`/chord` for the socket). So localhost, 127.0.0.1, `[::1]`, the LAN, a tailnet IP / MagicDNS name / `tailscale serve` HTTPS, or any other name that routes here all work without config.

**The owner's live dev server runs in tmux session `ultiv`** (API on 8787 under `node --watch`, Vite on 5173; the tailnet serves them as `https://<mac>.ts.net` and `:8443`). Do NOT restart it: `--watch` already reloads on source and `.env` changes. Only if it errors or a dependency change forces it, restart it yourself in that tmux session and read its log. Smoke tests and screenshot stacks use a spare random port, never 8787/5173.

**Gate for every change:** `vp check` → the six `vp exec tsc -p …` → `vp test` → `vp -C apps/web build` → `vp run smoke`. Re-run smoke after any dependency change; a clean typecheck alone does not prove runtime ESM wiring.

## Layout

- `packages/core` (`@ultiv/core`) — the kernel, no domain knowledge: `errors.ts` (shared tagged-error taxonomy: `NotFound`, `InvalidInput`, `Duplicate`, `Unavailable`, `AuthMissing`, `External`) and `runtime.ts` (`openRuntime(layer, key)` — builds a fully-provided Layer into a live service under a caller-owned scope; the door promise-land code enters through). Deps: `effect` only.
- `packages/ext` (`@ultiv/ext`) — the extension platform. `tool.ts` (pi-durable-shaped `Tool` + `gated` flag; pi-durable is a TYPE-ONLY dep here), `connector.ts` (auth specs — `none | env | vault` — + TypeBox-typed actions + `invoke`: validate → authenticate → perform; `vault` auth redeems a sealed item through an injected `AuthSource`, so credentials never cross a model-facing surface), `plugin.ts` (`definePlugin` + capability union `tool | connector | section` — new kinds extend the union), `registry.ts` (the `Registry` service: tools/sections/connector resolution; duplicate identities fail at build time), `vault.ts` (the credential vault: per-item AES-256-GCM DEK under a `VAULT_KEY`-derived KEK, masked metadata, `secret` vs `reference` access classes, contacts readable, single-use 60s grants for future executors, export/import of sealed forms), `plugins/http.ts` (reference HTTP egress connector + `vaultedHttpConnector` proving vault-backed bearer auth), `plugins/tinyfish.ts` (TinyFish live-web egress: `tinyfish` connector + the `web_search`/`web_fetch` tools, env `TINYFISH_API_KEY` — the plugin installs only when the key is present), `plugins/vault.ts` (`vault_list` masked metadata + `vault_contacts` — NO tool returns secret bytes, by construction; also the `ScopeHolder` the mind sets so ext plugins partition per profile), `plugins/artifacts.ts` (the artifact workspace: blob+JSON-sidecar store under `ARTIFACTS_DIR` (default `var/artifacts`), partitioned `{owner}/{profile}` when the scope holder is wired, plus `artifact_write` / `artifact_read` / `artifact_list` tools — writes are NOT gated, `artifact_delete` is — the server's REST serves the same store). Lifecycle is Effect layering, not plugin callbacks.
- `packages/mind` (`@ultiv/mind`) — the entity substrate: **one runtime, one entity per profile** (RFC 0001; the default profile is Ultius). Faculties: `converse` (pi-durable harness: `root`/`ensure(key, agent?)`/`submit`/`settle`/`turn`/`configure`/`agentOf` + `docs` for app-level session-scope documents + `projectTranscript`/`usageOf` — the projection and spend accounting every surface renders through), `decide` (Jev: `yesNo`/`pick`/`rate`/`ask`, independent of any conversation), `act` (tools assembled from the Registry; `gated` tools wrapped by the approval broker — gates ACTS, never ASKS; every execution rides `withAudit`, which stamps the acting conversation's profile), `generate` (one-shot structured completion for app features — titles, extraction; prompt-only JSON against a TypeBox schema with one repair retry, NEVER `response_format` on kenari; `mind.generate.complete/extract`), `tasks` (background sub-agent turns in their own durable conversations — `spawn`/`get`/`list` over the `ultiv.tasks` doc; when a task settles it WAKES the conversation that spawned it with the outcome, so parents end their turn instead of polling; task conversations are ADOPTED under the spawner's bot scope (kind "task"), so a task messages/artifacts/remembers AS its bot; on boot still-running tasks are RESUMED with a continuation input — restarts never reap work), `profiles` (`profiles/profiles.ts` — the `ultiv.profiles` doc + session registry v3 with profile/kind/participants; Bot Mode main chats (reset rotates the id), per-pair DM threads, the conversation→profile index persona/audit/artifact scoping all read, per-profile agents (model default + tool allowlist via `converse.ensure`'s agent override), `profiles/rooms.ts` — contextual rooms as tunnel records (no seat conversations — endpoints are the participants' own threads); the settings doc holds the ONE main bot (`mainOf`/`setMain`, REST `/api/main`); creation seeds an onboarding first turn from name/description/persona unless `onboard: false`; `ensureMain` is single-flight) and `profiles/section.ts`'s dynamic identity section: profile persona + a COMPACT sibling roster (name, id, ≤80-char role, at most 20 lines; details via the read-only `bots_list`/`bot_info` tools in `profiles/bots-tools.ts`, which follow the allowlist and never expose memory, files, vault or chats), or the substrate baseline for unmapped conversations), `mailbox` (`mailbox/mailbox.ts` — inter-bot messaging in CONTEXTUAL ROOMS (see `profiles/rooms.ts`): each participant has their OWN seat conversation so identity/memory scope stay per-entity; a pair may hold many rooms by topic; async only: admission is the contract, replies/NACKs wake the sender in their room seat (never the main chat), lineage hop caps (3), cycle refusal, per-pair rate (10/h), per-EXCHANGE cap (3 tool sends per sibling, counting only since the owner's last real instruction on the sending thread — a fresh brief resets it; human/REST/cron sends exempt; the message tool output reports the remaining budget so bots can acknowledge it), per-profile daily budgets, lane caps so bot traffic never starves the owner, bounded retries → dead-letter + escalation. THE ROOM IS A TUNNEL: delivery lands on the recipient's MAIN thread (thinking happens there, in the open); each send records its ORIGIN conversation (main or the session it was sent from) and replies/NACKs signal THAT thread — a session-origin exchange runs session ↔ counterpart-main. Wakes carry a finish SIGNAL + room id, never a transcript copy; the `room` tool reads a room's full envelope transcript from any endpoint initiation is OPEN by default (`canInitiate: ["*"]` — explicit list restricts, `[]` locks, REST/human sends always pass); `deliverExternal` enforces the stricter external trust class — no artifact grants, never autonomous), `memory` (`memory/` — v2, full contract in `docs/MEMORY.md`: five tiers in doc families `ultiv.mem.core/facts/graph/episodes/archive/proposals`; facts carry kind/importance/trust/validity/supersede history — nothing deleted but the owner's Purge; bilingual EN/ID ranked recall (BM25 + RRF, synonym lexicon, budgeted output) in `text.ts`/`lexicon.ts`/`search-index.ts`/`recall.ts`; the write guard (`guard.ts`) stamps origin off the input's bracket prefix and turn taint, refuses secrets and non-owner instructions; writes consolidate (dedupe → supersede → Jev/generate → add) in ONE transaction (`consolidate.ts`); core memory (owner 120w keeper-gated, bot 80w) rides its own `memory_core` prompt section (`profiles/section.ts`) and tool; the weekly tidy (Sundays 09:00 WIB, `apps/server/src/memory-tidy.ts`) only PROPOSES — nothing changes without the owner's accept; `ULTIV_MEMORY_V2=off` is a fallback to the v1 seam, not a full rollback; the v1 mirror and migration are gone (2026-10-28, nothing left to migrate)), `audit` (append-only JSONL of tool calls + approval/mailbox/escalation events, `AUDIT_LOG`, default `var/audit.jsonl`, entries carry the acting profile). Act extras: codemode (`act/codemode.ts`), the task tools (`act/task-tools.ts`), the message + room tools (`mailbox/tools.ts`), and the memory tools (`memory/tools.ts`). MCP connectors (`mcp/` here over `@ultiv/ext` `mcp/`: HTTP/SSE/stdio, config under `MCP_DIR`, OAuth via `MCP_OAUTH_CALLBACK_URL`) install live per server; bots manage them with `connector_*` tools whose changes are NEVER auto-approved, and keys arrive only by vault item or the `secret_request` secure field (`secrets/`, REST `POST /api/secrets/:callId`) — never as tool arguments, never in model context, transcripts, audit or logs. The act + codemode + task + profiles + mailbox + memory extensions install into a SHARED pi-durable registry (`converse/pi-registry.ts`) from `entity.ts` — late installs are legal, which breaks the tasks→converse layer cycle. `entity.ts` composes the services into `Mind` (`openMind(options)` is the promise-land entry; `mindLayer(options)` Effect-native) and wires the scope holder the ext plugins read. Owner rule enforced here: `turn` (submit → wait → commit) is the only path an input reaches a model — `generate` is the ONE sanctioned non-conversational exception, and it lives inside the mind. Model concurrency is bounded process-wide by the Gate (`providers/gate.ts`, `KENARI_MAX_CONCURRENCY`, default 4): the slot wraps stream CONSUMPTION (result()/iteration) — never wrap the stream call itself in a Promise, the harness iterates it synchronously (that faulted every live turn once); the gated methods are shadowed onto the instance so pi-ai's complete/completeSimple pass through too.
- `packages/contracts` — chord contracts (TypeBox). All `remote()`/`local()` definitions live here; both apps import `@ultiv/contracts` (`workspace:*`). `Session` is v5 (usage/model/effort state + `configure` + `input` attachments). The session registry, model catalog, tasks, artifacts, webhooks, cron jobs and the audit tail are NOT chord objects — they are plain REST on the server's HTTP handler with payload schemas in contracts, because chord 1.4.0's replicated-object wire desyncs on attach (see Pitfalls).
- `apps/server/src/main.ts` — `buildStack()`: `openMind({ plugins: [httpPlugin] })` (TinyFish egress auto-installs inside the mind when its key is present; the artifacts plugin always) → cron scheduler boot → chord `createHost` + `acceptWebSockets` (`ws`) + REST; `close()` stops the scheduler, tears down links, then the mind's scope (harness finalizers). Dev runs unbundled (Node strips TS types).
- `apps/server/src/identity.ts` — the principal seam: `x-ultiv-user` (header on REST, upgrade request on WS) resolves the `Principal`; `ownerOf`/`sessionKey` partition the registry and conversation keys (unauthenticated = `guest`). A real IdP replaces ONLY this module.
- `apps/server/src/session.ts` / `sessions.ts` — the app-facing boundary: `session.ts` is the chord Session object (replay, approvals + their audit records, configure, `input` with artifact attachments); `sessions.ts` is the REST-backed registry (owner-scoped list/create/remove + `touchSession`, which titles sessions through the generate faculty, falling back to truncation on any failure).
- `apps/server/src/rest.ts` — the REST dispatcher (routes live in `rest/`): sessions (profile-scoped), models, tasks, artifacts (per-profile dirs, raw bytes on GET with owner check), webhooks (+ `POST /hooks/:id?token=…` ingress), cron (tz-aware per profile, auto-disable on 3 consecutive failures), profiles/bots (CRUD, Bot Mode ensure/reset, archive, purge cascade, export/import bundles, set-main `/main`, `GET /api/main`; the main bot and last bot are not removable), rooms (`GET /api/rooms` (+`?bot=`), `GET /api/rooms/:id` → the tunnel transcript as one speaker-labelled timeline, `/say` supervision into the bot's endpoint — never sessions), mailbox (human-instructed sends, dead-letter list), vault (human-only secret entry, masked responses), approvals (the cross-profile inbox + REST decide), vault bindings (`GET /api/vault/bindings`, `PUT|DELETE /api/vault/:id/binding`), push (`/api/push/config|subscribe|unsubscribe|presence|test`), memory, memory v2 (`rest/memory-v2.ts`: `GET /api/memory/v2` facts/core/proposals, proposal accept/reject, core CRUD, `POST /api/memory/tidy/run`, `POST /api/memory/purge` — irreversible), audit tail (`?profile=` filter); owner scoping rides `x-ultiv-user`. Mind-service calls here go through `Effect.runPromise` — they are Effects, not Promises.
- `apps/server/src/deliver.ts` / `webhooks.ts` / `cron.ts` / `sensors.ts` — the trigger path: webhooks, cron and calendar sensors deliver into sessions through `deliverToSession` — admission is the contract; the turn settles in the background, and a failed TURN is never a failed delivery. Routine wakes STEER a busy turn (`whenBusy: "steer"`); sensors queue as follow-ups. Cron jobs live in the `ultiv.cronjobs` doc; the scheduler re-arms from it on refresh and on boot. Cron and webhook fires both write WRITE-AHEAD receipts into the `ultiv.routine-events` doc (the routines faculty in the mind — see `docs/ROUTINES.md` for the whole contract); webhook ingress validates size/rate/schema BEFORE the ack (ack body carries the correlation `eventId`), deliveries debounce per session (`WEBHOOK_DEBOUNCE_MS`, default 2.5s), retry 3x, then dead-letter with an audit escalation. The sensor loop polls per kind — the calendar ICS feed, per-sensor RSS urls, and watch urls (edge-triggered fingerprints) — dedups by the source's natural key (or fingerprint transition), and wakes as a follow-up.
- `apps/web` — React 19 + TanStack Router + shadcn on Base UI + Tailwind 4 (no Effect in the client); `vite.config.ts` imports `defineConfig` from `"vite-plus"` (vp rewrites this on `vp migrate`) and loads `tanstackRouter` → `tailwindcss` → `react` plugins. See **Web UI** below.
- Root `vite.config.ts` — workspace-level vp config; only sets oxfmt `ignorePatterns` (the generated route tree).

## Web UI

- **Routing: TanStack Router, file-based.** Routes live in `apps/web/src/routes/`; `__root.tsx` is the one layout (desktop side nav `components/app-nav.tsx` + phone tab bar, `main` sets `--chat-bottom` for the floating composer). Routes: `/` (chat with the current bot, `?bot=<id>`; onboarding when there are no bots), `/c/$sessionId` (one chat), `/bots`, `/vault`, `/routines`, `/history`, `/rooms` ("Bot talks", `?bot=` + `?room=`; reached from the bot switcher and the desktop side nav, not a phone tab). `/sessions/$sessionId` only redirects to `/c/$sessionId`. Tabs are `Link`s with `aria-current`; the Chat tab returns to the last bot (`lastBot` in `lib/app-state.tsx`). The router plugin regenerates `src/routeTree.gen.ts` on `vp dev` / `vp build`. It is committed, never hand-edited, and excluded from oxfmt. `src/router.ts` creates the router and registers its type.
- **Components: shadcn, style `base-nova`, on Base UI (`@base-ui/react`), not Radix.** Config is `apps/web/components.json`; add components with `vp -C apps/web exec shadcn add <name>`. Primitives live in `src/components/ui/` (badge, button, card, code-block, collapsible, dev-details, dialog, empty-state, input, input-group, list-row, scroll-area, section-header, select, separator, spinner, textarea, trace) — reuse them (Select, SectionHeader, EmptyState/ErrorState, ListRow, DevDetails) instead of one-off markup. Dialogs are bottom sheets on phones and centred on `sm+`. Markdown goes through `LazyMarkdown` (react-markdown + shiki in a lazy chunk). Icons: `lucide-react`.
- Base UI composes with the **`render` prop, not `asChild`**. When a `Button` renders a non-button element (e.g. a router `Link`), also pass `nativeButton={false}` — see `routes/index.tsx`.
- **Styling: Tailwind 4, CSS-first** — no `tailwind.config`; theme tokens and the `dark` variant live in `src/index.css` (imports `tailwindcss`, `tw-animate-css`, `shadcn/tailwind.css`, Geist variable font). Use the semantic tokens (`bg-background`, `text-muted-foreground`, …), not raw colors.
- `cn()` comes from the `cn` package (`src/lib/utils.ts` re-exports it), not clsx + tailwind-merge.
- Alias `@/*` → `apps/web/src/*`, declared in both `vite.config.ts` (`resolve.alias`) and `tsconfig.json` (`paths`) — keep them in sync.
- Chat chrome (header pill = bot switcher, composer, tab bar) floats translucent over the transcript; keep text sizes ≥ `text-xs`, radii 6/10/14, border-only cards.

## AI providers

- **Owner rule: the mind is the only provider consumer.** Every LLM chat/generation goes through pi-durable conversations inside `@ultiv/mind` (`converse.turn` = `submit` → `wait` → `commit`), never raw `models.complete()` in app code. Conversations start on the kenari default (`KENARI_MODEL`, fallback `KENARI_FALLBACK_MODEL` in `packages/mind/src/config.ts` — grep both when switching); sessions override via `converse.configure(conversation, { model, effort })` (durable `conversation.configure`; read back with `agentOf`, which sanitizes out-of-list efforts). The catalog in `providers/kenari.ts` — DeepSeek 4.1 Flash (default), GLM 5.3 Flash, MiniMax M3.1 Flash, all through kenari for now — is verified against `GET /v1/models` (2026-10-25), priced from models.dev where present (gateway metadata + IDR→USD ÷ 16,500 otherwise). Efforts are PER MODEL, from the gateway's `supported_reasoning_levels`: deepseek off/low/high/max (toggleable), glm-5-3-flash low/high/max, minimax-m3-1-flash low/medium/high/xhigh/max (glm and minimax always reason — no off); `off` maps to the gateway's `none`, and `configure` snaps an out-of-list effort to the model's default. Usage surfaced to contracts/UI is TOKENS only — cost stays internal to pi-ai (`COST_RATES` in providers/kenari.ts). Compaction compacts at **75%** of each model's context window (`kenariCompaction()` in Harness `settings.compaction`, per-model overrides). Jev decisions have an independent entry: `mind.decide.*` — the same faculty also appears as `jev`/`jev_score`/`jev_pick`/`jev_rate` agent tools via the decision plugin (descriptions are first-person faculty: "your own decision faculty, Jev" — Jev is part of each bot's own mind, never narrated as an external helper).
- **kenari.id** — OpenAI-compatible gateway, wired as a pi-ai `createProvider` (`openAICompletionsApi`), auth `envApiKeyAuth` on `KENARI_API_KEY`. Model id comes from `KENARI_MODEL` (fallback constant `KENARI_FALLBACK_MODEL` lives in `packages/mind/src/config.ts` — the only other site; grep both when switching). Spec source: models.dev `kenari/deepseek-v4-1-flash` (reasoning model, 1M ctx / 384k out). Before switching models: verify the id exists in `GET $KENARI_BASE_URL/models` and run the probe. Never use `response_format: json_object` — it hangs some kenari models; ask for strict JSON in the prompt. The model misreports its own id (`model_used` says gpt-4o/gpt-4.1) — ignore it; routing follows the requested id.
- **Typesafe.AI (Jev)** — `@typesafe-ai/sdk`, `client.systemOne({ state, questions })` with `noul`/`choice`/`score`/`box` builders; key `TYPESAFE_API_KEY`, model `jev-latest` (`TYPESAFE_MODEL` overrides). Jev is a typed decision model, not a chat provider: `decide/decide.ts` wraps it behind the narrow `JevGateway` seam (`decide/gateway.ts`) so tests substitute fakes. Unconfigured keys fail LOUDLY but lazily: `decideService(undefined)` fails every call with `Unavailable`; the decision plugin simply isn't installed.
- `.env` holds provider keys — server-side only; never commit, print, or ship to the client. Load it with `vp node --env-file=…` (or the `dev`/`start` scripts), never by echoing it.

## Features (where they live)

- **Each profile is its own entity.** One runtime, many bots: persona, memory, artifacts, vault scope, tool allowlist and audit are per profile (the conversation→profile index scopes them). The default profile is Ultius. Never describe the platform as "one entity".
- **Redirect now** — `packages/mind/src/converse/redirect.ts` + the busy send menu in `apps/web` (`send-button.tsx`, `lib/send-mode.ts`). Steer (default) waits for the next tool boundary; Redirect stops the turn at the nearest safe point (abort streaming; let a running tool round finish within 15 s; deny a waiting approval) and answers the new message. Queued messages stay queued; a cut reply is marked interrupted.
- **Credential broker** — `packages/ext/src/broker/` (adapter seam `adapter.ts`, `http-adapter.ts`, `net-guard.ts` SSRF/DNS guard, `redact.ts`, `bindings.ts` store beside the vault, `http-request-tool.ts`) wired by `packages/mind/src/act/broker.ts`. The `http_request` tool spends a sealed secret only within the item's binding (hosts, methods, path prefixes, placement header/bearer/basic/query, bots); https only (localhost http opt-in); auth dropped on cross-host/off-prefix redirects; ≤5 redirects, 256 KB request, 512 KB response, 20 s; responses scrubbed; audited as kind `credential` (never the secret). First use per credential+host raises its own card that "Always allow" never covers (server and UI). Bindings are edited in the Vault ("Allow web use"); deleting an item drops its binding. Other adapters (ssh/git/SMTP/DB) implement the same interface later.
- **Tasks** — `task_message` (the parent steers a running task; arrives as `[from parent]`), `notify_owner` (a task's rare progress line: ≥2 min apart, ≤280 chars), the cap `ULTIV_MAX_RUNNING_TASKS` (3), and the web task pill above the composer (`components/tasks-pill.tsx`).
- **Mailbox deadline** — each bot-to-bot request expires after `MAILBOX_DEADLINE_MS` (default 15 min) and NACKs the sender.
- **PWA + Web Push** — web: `apps/web/public/` (`manifest.webmanifest`, `icons/`, `sw.js`, `offline.html`), `lib/push.ts` (SW registration, per-tab presence heartbeat, subscribe), `lib/push-support.ts`, the Notifications setting on `/bots` (`components/push-toggle.tsx`). The service worker caches ONLY `offline.html` + the icon at install; it never caches `/api`, `/chord`, `/hooks`, page HTML or any runtime response. Server: `apps/server/src/push/` — VAPID from `.env`, owner-scoped subscriptions in `PUSH_DIR` (default `var/push`, 0600), endpoints restricted to the browser push services (SSRF guard), a notifier that skips while any of the owner's tabs is visible, collapses the same tag for 30 s (plus the Topic header) and caps 6/min per owner, pruning 404/410 subscriptions. Pushes fire on: task done/failed (`tasks.listen`), approval waiting (`approvals.listen`), a webhook/cron/sensor turn settling with a reply (`deliverToSession(..., source)`), a bot-to-bot message timing out (`mailbox.onExpired`). Payloads carry the bot name and event kind only (no tool input, results or message text); a tap opens `/c/<sessionId>`. Push needs a secure origin: the HTTPS tailnet URL (or localhost); on iPhone only from a Home Screen install.

## Conventions

- ESM only; tabs (oxfmt via `vp fmt` enforces); `import type` for type-only imports (`verbatimModuleSyntax`).
- Relative imports use explicit `.ts` extensions (`allowImportingTsExtensions` + Node type stripping).
- **Shared versions live in the pnpm catalog** (`catalog:` in `pnpm-workspace.yaml`): every dependency used by two or more workspaces (`effect`, `typebox`, `croner`, the `@earendil-works/*` set, the `@modelcontextprotocol/*` pair) is declared `"catalog:"` in each `package.json` and versioned ONCE in the catalog. Adding one of them to another workspace: write `"catalog:"` in its manifest, then `vp install`. Promote a dependency into the catalog the moment a second workspace needs it.
- `typebox` stays pinned EXACT `1.3.27` in the catalog — chord requires exactly this version; anything else nests a duplicate copy. The `@earendil-works/*` packages are pinned exact and ship in lockstep: bump them together, and typebox only with chord.
- TypeBox is the only schema language at the chord boundary; Effect Schema stays inside effect services.
- Strict TS: `exactOptionalPropertyTypes` (never assign explicit `undefined` to optional props), `noUncheckedIndexedAccess`.

## Repo rules (set by the owner)

- **vp only** — no `npm`/`npx`/`pnpm`/bare `node` in commands, scripts, docs, or CI. If vp lacks a command, use `vp pm …` and note why.
- MAX 500 LoC per file; MAX 100 LoC per function/component — at 80 LoC, split.
- Code must be linted (`vp check`), typechecked (`vp exec tsc -p …` ×6), and tested (`vp test`) — the gate above is the proof. Never claim code is "tested" without it.
- Work done = work committed: atomic commits, conventional-commit messages (`feat:`, `fix:`, `chore:`, `build:`, `docs:`).

## Pitfalls

- **Never add `vite` or `vitest` as a dependency.** vp owns them via the pnpm catalog (`vite` → `@voidzero-dev/vite-plus-core`); a standalone vite makes `vp build` fail. Run `vp migrate --no-agent` if the alias drifts.
- `BACKGROUND_CONTEXT` is NOT exported from the chord root — import it from `@earendil-works/chord/context`.
- pi-durable's README examples drift from its 1.4.0 types — trust `dist/*.d.ts`: `AssistantEntry` stores the message in `record.model[0]` (`[AssistantMessage]`), `settled.answer` is an `EntryId`, `commit()` may return `undefined`.
- pnpm 12 gates build scripts with `allowBuilds` in `pnpm-workspace.yaml` (not the old `ignoredBuiltDependencies`). `@google/genai` and `protobufjs` are explicit `false` (vetted no-ops) — never flip to `true` without reading the script. To allow one deliberately: `vp add <pkg> --allow-build <pkg>`.
- `vp install` may report "Agent skills awaiting approval" (currently `@tanstack/react-router`, `@tanstack/router-plugin`). vp 1.4.0 does not forward pnpm's `approve` (`vp pm approve` errors; only `approve-builds` exists), so leave them unapproved — approving is the owner's call, not an agent's.
- Files Node executes directly (server, probe, smoke) must be erasable-syntax-only TS: no enums/namespaces/parameter properties.
- Annotate chord `principal` callbacks with the app `Principal` type — inline object literals widen string literals and break `Host<P>` inference.
- `tsconfig.json` files must stay strict JSON (tooling validates them; no comments).
- Effect 4 (the repo's version) drifts from Effect 3 habits: there is NO `Effect.catchAll` (use `Effect.match` / `catchTag` / `catchIf`); `ConfigError` imports from `"effect/Config"`, not the root; `Layer.merge` is binary (chain `.pipe(Layer.merge(…))` or `mergeAll`); `Layer.buildWithScope` yields a `Context` — extract the service with its key; `Config`'s env provider snapshots `process.env` at FIRST use, so tests must set env at module load, never mid-test; `Data.TaggedError` instances yield directly (`return yield* new NotFound(…)`).
- Effect Layers compose services; a parameterized layer is a function returning a Layer. Long-lived runtimes (server, probe) go through `openRuntime(layer, key)` in `@ultiv/core` — never `Effect.scoped` around a service that must outlive the call.
- Structured tool outputs must be JsonValue-compatible: use `type` aliases, not `interface`, for result shapes (interfaces lack implicit index signatures).
- `vp node` cannot resolve node when invoked INSIDE a `vp run` script — root scripts delegate (`vpr smoke` → the server workspace script) instead of nesting `vp node`.
- chord 1.4.0's replicated-object attach desyncs over the wire: attaching an object whose state carries data (or publishes during attach) trips `ChordError: invalid/protocol: ack N outside 0..N`, after which the link drops publications. It logs on every Session attach — delivery still works (the task's publications resync), but do NOT add more replicated CRUD objects over the wire: the session registry is REST for exactly this reason.
